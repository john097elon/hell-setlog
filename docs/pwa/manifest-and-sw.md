# PWA: Manifest, Service Worker, and Offline Strategy

## Web App Manifest

The manifest is generated at build time by `vite-plugin-pwa` from `vite.config.ts`. It is served as `manifest.webmanifest`.

## Service Worker Strategy

**Build Mode**: `generateSW` (auto-generated by Workbox).
**Registration Mode**: `prompt` (changed from `autoUpdate`).
Users choose when to apply updates via the `PWAUpdatePrompt` component rendered in `main.tsx`.

### Cache Plan

- **Precached**: `**/*.{js,css,html,ico,png,svg,woff2}` (23 entries, ~302 KB)
- **Excluded from cache**: `**/api/**` and `**/media/**`
  - API routes are dynamic/user-specific. Caching would serve stale data.
  - Media files require bearer auth. The frontend fetches them through the Axios client.
- **Runtime caching**: `/assets/avatars/*.(png|svg)` -> CacheFirst, cache name `avatar-cache`, 30 days, 50 entries max.

### Update Flow

1. Page loads -> SW installs new version -> `waiting` state -> `onNeedRefresh` fires.
2. UI shows banner with update/dismiss buttons.
3. User clicks update -> `messageSkipWaiting()` -> new SW activates -> page reload.
4. If dismissed, update is deferred to next page load.

## Offline / Network Resilience

### Offline Detection

`OfflineDetect` component in `main.tsx` listens for `online`/`offline` events.
Shows a top banner when connectivity drops; auto-hides on reconnect.

### What Works Offline

- Previously visited pages (HTML/JS/CSS from precache).
- Avatar images from runtime cache.

### What Requires Network

- Workout CRUD, setlog submission, auth, party data, character stats, media.

### Request Resilience (api.ts)

1. **Idempotency keys**: Setlog POSTs carry `X-Idempotency-Key` header.
   In-flight duplicate POSTs with the same key are cancelled.
2. **Exponential backoff retry**: Network errors and 5xx (excl. 409) retried up to 2x with 1s/2s delay.
3. **Timeout**: 15 seconds.
4. **401 auto-redirect**: Expired tokens redirect to `/login`.

### Workout Draft

`useWorkoutDraft` hook persists party ID and notes to localStorage.
Draft is restored on page refresh; cleared on successful workout creation.

## Dev vs Production URLs

| Context | API | Frontend | Notes |
|---|---|---|---|
| Local dev (Vite) | :8001 | :5173 | Vite proxies /api to :8001 |
| Docker Compose | :8000 | :8000 | SPA served by uvicorn |
| Staging/Prod | HTTPS same origin | Same origin | Caddy -> app:8000 |

The port mismatch between dev (`:8001` backend, `:5173` frontend) is intentional.
In Docker/production, the compiled SPA is served by the same uvicorn process on one port.

### canonical_origin by Environment

- Development (no `.env`): http://localhost:5173
- Docker Compose: http://localhost:8000
- Staging: https://staging.example.com
- Production: https://example.com

## Out of Scope: TWA / Store Packaging

Trusted Web Activity for Google Play Store and iOS Safari standalone packaging
are **not implemented** and **not planned for beta**.
