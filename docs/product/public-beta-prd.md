## 1. 제품 개요

### 1.1 목표 사용자

| 구분 | 내용 |
|---|---|
| **1차 타겟** | 한국 20-35세 운동 초중급자, 헬스 경험 1년 미만 |
| **2차 타겟** | 혼자 운동하는 직장인, 운동에 재미를 붙이고 싶은 사람 |
| **제외** | 전문 운동선수, PT 전용 사용자, 경쟁/순위 기반 동기부여 선호자 |

### 1.2 해결할 문제

| 문제 | 현재 상태 | Hell Setlog 접근 |
|---|---|---|
| 혼자 운동 의지 유지 어려움 | 운동 앱은 단순 기록 도구 | 파티 + 캐릭터 성장으로 동기 부여 |
| 운동 기록의 지루함 | 텍스트/숫자만 기록 | 세트로그 + 파티 피드 + 반응으로 사회적 경험 |
| 운동 성취감 부족 | 종이/앱에 체크만 | 캐릭터 능력치 상승 + 레벨업 돌파 효과 |
| 운동 습관 형성 어려움 | 별도 동기 장치 없음 | 스트릭 + 파티원 반응 + 캐릭터 관여 |

### 1.3 핵심 Job

> **"사용자가 혼자 하는 운동을 파티원들과 함께 기록·공유하며, 캐릭터를 성장시키는 재미있는 경험을 통해 운동 습관을 형성한다."**

### 1.4 Activation 순간

사용자가 제품 가치를 처음 체감하는 순간은 다음 3단계다:

| 단계 | 행동 | 인지할 가치 |
|---|---|---|
| **A0** | 회원가입 완료 | 캐릭터 생성 + 7종 능력치 기본 부여 |
| **A1** | 파티 참여 (랜덤매치/초대코드) | 혼자가 아님을 인지 |
| **A2 (Activation)** | **첫 운동 시작 → 세트로그 등록 → 운동 종료 → 캐릭터 성장 → 파티 피드 반응** | 핵심 루프 1회 완주 |

> **Activation = A0 + A1 + A2를 24시간 이내 완료한 사용자**

## 2. 핵심 루프 사용자 여정

### 2.1 정상 여정 (Happy Path)

회원가입 → 캐릭터 생성 → 파티 참여(랜덤매치/초대코드) → 운동 시작 → 세트로그 기록(start/mid/end) → 운동 종료 → 캐릭터 성장(7부위 potential + level) → 파티 피드 공유 → 파티원 반응(🔥 💪 👏) → 다음 운동(스트릭 유지)

### 2.2 이탈 좌초 여정

| 상황 | 증상 | 대응 |
|---|---|---|
| 회원가입 후 파티 미참여 | A1 미도달, 24시간 경과 | 다음 로그인 시 파티 안내 |
| 파티 참여 후 운동 미시작 | 48시간 동안 workout 0 | Stage 2 push 예정, 베타 미대응 |
| 운동 중 세트로그 미기록 | setlog 0개로 종료 | 종료 시 기록 안내 메시지 |
| 운동 종료 후 7일 재방문 없음 | D7 이탈 | Stage 2 재참여 계획 |
| 파티 강퇴 | kicked 상태 | /parties에서 새 파티 안내 |
| 파티 탈퇴 | leave | 새 파티 참여 유도 |

### 2.3 재진입 여정

| 이탈 상태 | 트리거 | 경로 |
|---|---|---|
| 운동 경험 있음, 파티 없음 | URL 재방문 | /login → /parties |
| 운동 경험 있음, 파티 소속 | URL 재방문 | /login → /party/{id} |
| 회원가입만 하고 이탈 | 브라우저 재방문 | /login → /parties 파티 가입 유도 |

## 5. 성공 지표 정의

### 5.1 지표 계산식

| 지표 | 정의 | 계산식 |
|---|---|---|
| 회원가입 | 계정 생성 완료 | COUNT(users.created_at) |
| Activation | 가입 24시간 내 A2 달성 | COUNT(A2) / COUNT(signup 동일기간) × 100 |
| 완료 운동 | status=ended workout | COUNT(workouts WHERE status=ended) |
| 파티 참여율 | active member≥1 파티 비율 | COUNT(parties WITH active≥1) / COUNT(parties) |
| 캐릭터 관여 | body_stat level 변화 사용자 | COUNT(users any level up in period) |
| D1 유지 | 가입翌日 workout 기록 | COUNT(D1 workout) / COUNT(signup) × 100 |
| D7 유지 | 7일 내 2회차 workout | COUNT(7일 내 workout≥2) / COUNT(signup) × 100 |
| 스트릭 유지율 | current_streak ≥ 3 | COUNT(streak≥3) / COUNT(active users) |
| 세트로그/운동 | 운동당 평균 setlog | AVG(COUNT(setlogs) PER workout) |
| 반응 참여율 | reaction 단 사용자 비율 | COUNT(reacted) / COUNT(workout users) × 100 |

### 5.2 베타 목표 기준

| 지표 | 목표 | 측정 |
|---|---|---|
| Activation rate | >= 40% | 전체 기간 |
| D1 유지율 | >= 30% | 매일 |
| D7 유지율 | >= 15% | 매주 |
| 운동당 평균 setlog | >= 3개 | 매주 |
| 파티 1인당 운동 주기 | 주 2회 이상 | 매주 |
| 반응 참여율 | >= 20% | 전체 기간 |

### 5.3 필수 이벤트 속성

모든 이벤트는 event_name, user_id, timestamp, session_id 포함. 이벤트별 추가 속성은 이벤트 Taxonomy 문서 참조.

## 7. Go/No-Go 조건

| 조건 | 기준 | 확인 |
|---|---|---|

## 8. 오픈 선택지

### 8.1 파티 매칭 방식

| 안 | 설명 | 권고 |
|---|---|---|
| **A안 (현행)** | 수동 생성 + 랜덤매치 병행 | **유지 (권고)** |
| B안 | 랜덤매치 전용 | 지인 운동 불가 |
| C안 | 수동 생성 전용 | 첫 진입 장벽 |

### 8.2 캐릭터 성장 속도

| 안 | 1회 potential | 1→2 소요 | 권고 |
|---|---|---|---|
| **A안 (현행)** | 5~15 random | 7~20회 | **유지, 베타 데이터 후 재평가** |
| B안 | 10 고정 | 10회 | 예측 가능하나 지루함 |
| C안 | 부위 차등 | 부위별 상이 | 복잡도 증가 |

| 항목 | 질문 | 결정 |
